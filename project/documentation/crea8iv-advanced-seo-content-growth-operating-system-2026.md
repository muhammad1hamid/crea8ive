## 1. Executive Recommendation

The current direction is strong: regular blogs, AI search topics, local SEO, founder authority, branded thumbnails, RSS, sitemap verification, and schema-aware publishing.

The next improvement is to stop thinking of this as only a blog calendar.

The better model is:

**Daily Organic Growth Engine = Content + Technical SEO + Internal Links + Authority + Distribution + Measurement**

One blog per day can work, but only if every post is genuinely useful, differentiated, internally linked, visually polished, indexed, distributed, and later refreshed. If the site publishes daily without strong QA, proof, originality, and promotion, it can become volume without authority.

For CREA8IV MEDIA, the best advanced cadence is:

| Day Type | Work | Purpose |
|---|---|---|
| 4 days/week | Publish new high-quality blog or guide | Build topical authority and capture new queries |
| 1 day/week | Refresh/update older post | Improve existing rankings and prevent content decay |
| 1 day/week | Authority/link/distribution sprint | Improve DR, mentions, citations, and AI corroboration |
| 1 day/week | Technical SEO + analytics sprint | Fix crawl, Core Web Vitals, schema, tracking, and conversion issues |

If the team wants to keep daily publishing for a 60-90 day sprint, keep it only under a stricter standard:

- no thin posts
- no repeated topics
- no keyword stuffing
- no default thumbnails
- no publish without live verification
- no post without internal links, CTA, schema, RSS, sitemap, and distribution plan
- every 7th day must include a performance/content-quality audit

## 2. Why One Blog Per Day Can Be Effective

Daily publishing can be effective when the site needs fast topical coverage and has enough editorial quality control.

It helps with:

- building topical depth around AI Search, SEO, GEO, AEO, LLMO, local SEO, websites, Google Ads, Meta Ads, and automation
- creating more internal link targets for service pages and tools
- giving Google and AI systems more crawlable evidence about what CREA8IV does
- creating fresh assets for LinkedIn, Medium, Quora, Reddit discussions, Threads, YouTube scripts, and email
- supporting long-tail queries that competitors may ignore
- building a visible publishing rhythm that helps brand trust

But daily publishing becomes weak when:

- posts repeat the same angle
- the content is generic
- posts do not earn links or mentions
- there is no topical architecture
- old posts are never refreshed
- posts are published but not distributed
- there is no Search Console or conversion measurement
- technical performance gets worse because of image and script bloat

Google's helpful content guidance is clear: content should be people-first, original, substantial, trustworthy, and created to help users. So daily cadence must never become the main goal. The goal is usefulness, authority, and measurable business impact.

## 7. Technical Publishing Standard

No post is complete until it is live and verified.

Required pipeline:

1. Add markdown draft under `project/documentation/blog-drafts/`.
2. Add branded thumbnail under `frontend/public/wp-content/uploads/YYYY/MM/`.
3. Add `cover_image_url` and `cover_alt`.
4. Run `npm run export` in `frontend`.
5. Run `node scripts/test-rss-feed.mjs` when RSS/feed output changes.
6. Run `bash scripts/deploy_to_hostinger.sh` from project root.
7. Verify live URL returns `200`.
8. Verify `/blog/` includes the post.
9. Verify `/sitemap.xml` includes the URL.
10. Verify `/rss.xml` includes the URL and thumbnail.
11. Verify live article HTML contains custom thumbnail in hero, OG/Twitter metadata, and JSON-LD.
12. Verify live thumbnail URL returns `200 image/webp`.
13. Only then mark the post `Published`.

If deployment or live checks fail, mark:

- `Blocked before live publish`
- `Local only - not published`

Never mark as published based only on local files.
